F0.2 — Bootstrap and first SAT ingestion
========================================

Status
------

F0.2 is complete at the architectural and focused-test level.

Implemented
-----------

- Python package scaffold with Python 3.11+.
- Domain DTOs separated from SQLAlchemy persistence.
- SQLite persistence for KnowledgeSpace, Source, ImportRun, SourceItem,
  KnowledgeItem, KnowledgeSection, KnowledgeAttribute and Evidence.
- Stable SourceItem and KnowledgeItem identifiers.
- Canonical checksum for source records.
- Import states: new, changed and unchanged.
- ImportRun history with source fingerprint.
- Re-import idempotency.
- SourceAdapter separated from KnowledgeNormalizer.
- SAT.mdb isolated behind the Gredos SAT adapter and extractor boundary.
- MdbToolsExtractor and portable NeutralJsonlExtractor.
- Strict UTF-8 extraction and explicit preservation of Access NULL values.
- Deterministic CONSULTAS normalization without LLM.
- HISTORICO preservation as independent SourceItem rows.
- Generic parent_external_id for source-level hierarchy.
- Orphan HISTORICO rows preserved without inventing parents.
- Focused tests for idempotency, updates, traceability, SAT mapping and history.

Real SAT.mdb findings
---------------------

The source is a Microsoft Access database of approximately 10–11 MB.

Relevant tables confirmed include CONSULTAS, HISTORICO, DOCUMENTOS, IMAGENES,
CLASIFICACION, PRIORIDAD and SITUACION, alongside operational SAT tables.

CONSULTAS has 3,249 rows and 22 fields. The extraction found fields beyond the
initial design notes, including FECHAAVISO, HORAAVISO and CodigoWeb. SourceItem
raw_content preserves all original fields, including fields not normalized in
F0.

HISTORICO has 10,369 rows. All 10,369 ID_HISTORICO values are present and
unique. 10,188 rows reference a currently existing CONSULTAS row. 181 rows are
orphans relative to the current CONSULTAS table. 2,641 consultations have at
least one historical entry and 608 have none. Among consultations with history,
the average is 3.86 entries and the maximum observed is 149.

Neutral export
--------------

The reproducible Access boundary is:

    SAT.mdb
        -> mdbtools
        -> JSONL neutral export
        -> GredosSatAdapter
        -> SourceItem

The validated neutral export contains:

    CONSULTAS  3,249 rows
    HISTORICO 10,369 rows
    total      13,618 rows

The source SHA-256 recorded during the validated run was:

    e682ec32475183ec7eb0569d048edc4aa0deff6189ee946c2558a315fe33cc85

The raw mdb-export output decoded as strict UTF-8 with zero replacement
characters. NULL preservation was corrected before closing F0.2. The validated
CONSULTAS export contained 12,095 NULL values and zero empty-string values.

Validated real sample
---------------------

A controlled sample of 10 real CONSULTAS rows was imported into SQLite.

First import:

    new=10 changed=0 unchanged=0 knowledge_items=10

Second import:

    new=0 changed=0 unchanged=10 knowledge_items=0

The store contained two ImportRun rows but only 10 SourceItem, 10 KnowledgeItem
and 10 Evidence rows, demonstrating idempotency and separation between import
history and current knowledge.

A full trace of CONSULTAS:1 confirmed preservation of all 22 source fields,
normalization into support_case plus symptom/environment/solution/notes,
program/module attributes, and Evidence back to locator CONSULTAS:1.

Semantic decisions
------------------

Deterministic import does not prove source truth. Imported KnowledgeItem rows
start as status=active and confidence=NULL. Evidence confidence=1.0 means the
source linkage is certain, not that the source statement is objectively true.

CONSULTAS is normalized into initial support_case knowledge.

HISTORICO is preserved as source material only. It is deliberately not turned
into KnowledgeItem automatically because its content mixes technical knowledge
with operational history. Later AI stages may classify or extract candidates
from it.

What F0.2 deliberately does not include
----------------------------------------

- LLM calls.
- Embeddings or vector search.
- RAG.
- Entity and relation extraction.
- KnowledgeCandidate or KnowledgeRevision.
- DOCUMENTOS and IMAGENES ingestion.
- Automatic technical-knowledge extraction from HISTORICO.

Next phase
----------

F1 should build basic knowledge CRUD and manual knowledge entry on top of the
validated canonical model. Classical retrieval remains a later phase so that
F1 first proves the system can start empty and be populated without SAT.
